# Design decisions

One row per UI/design question that reached an answer I can point at in a
repo file: the token layer (`web/src/app.css`, `extension/src/lib/tokens.css`),
a component, a design doc under `docs/*-design.md`, or a commit message.
`Round` names the source. `Rule it creates` is usually empty; it is filled
only when the decision produced something a component can violate - a row
with a rule is binding on an implementer, a row without one is context.
Prose belongs under the table, never inside it.

There are no hand-built HTML option mocks in this repo, so nothing is
retired here. The drawing for anything new happens in the **Pitchbox Design
System** project on Claude Design; this file is the answer.
