# Design decisions

One row per UI/design question that reached an answer I can point at in a
repo file: the token layer (`web/src/app.css`, `extension/src/lib/tokens.css`),
a component, a design doc under `docs/*-design.md`, or a commit message.
`Round` names the source. `Rule it creates` is usually empty; it is filled
only when the decision produced something a component can violate - a row
with a rule is binding on an implementer, a row without one is context.
Prose belongs under the table, never inside it.

There are no hand-built HTML option mocks in this repo, so nothing is
retired here. The drawing for anything new happens in the **Pitchbox Design
System** project on Claude Design; this file is the answer.

## Unresolved

- **A deliberate brand hue.** No file records a choice to stay hueless. The
  `:root`/`.dark` palette is the unmodified shadcn neutral scaffold from the
  `feat(web): init shadcn-svelte` / `feat(web): scaffold sveltekit + tailwind 4 +
shadcn-svelte` commits: chroma 0 on every token except `--destructive`,
  `--link` (D3), and `--sidebar-primary` in `.dark`
  (`oklch(0.488 0.243 264.376)`), which is dead CSS - no `ui/sidebar`
  primitive was ever adopted (`web/src/lib/components/ui/` has no `sidebar/`
  folder) and grepping both `app.css` files plus every `.svelte` file for
  `sidebar-primary` finds no consumer anywhere outside the two token
  declarations themselves. If a brand hue is ever wanted, it is a decision
  still to make, not a reversal of one already taken.
